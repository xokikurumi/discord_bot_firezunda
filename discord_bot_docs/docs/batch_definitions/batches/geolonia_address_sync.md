# Geolonia 住所同期

## 1. 基本情報

| 項目 | 内容 |
|---|---|
| バッチ ID | BATCH-013 |
| 処理名 | Geolonia 住所同期 |
| 実行方式 | 定期処理 |
| 起動契機 | P2PQuake 監視開始時 |
| 有効化設定 | `GEOLONIA_ADDRESS_SYNC_ENABLED` |
| チェック間隔 | `GEOLONIA_ADDRESS_SYNC_CHECK_INTERVAL_SECONDS` |

## 2. 処理概要

住所データを取得し、町域ごとの代表緯度経度を `b_geolonia_address` に保存する。
保存した住所データは、地震・津波関連通知で地点名から座標を解決する際に利用する。

## 3. 実行判定

| 条件 | 判定 |
|---|---|
| 同期履歴が存在しない | 実行する |
| 最終同期日時が最新予定同期日より古い | 実行する |
| 最終同期日時が最新予定同期日以降 | スキップする |

## 4. 予定同期日

| 現在日時 | 最新予定同期日 |
|---|---|
| 1 月 1 日より前 | 前年 6 月 1 日 |
| 1 月 1 日以上、6 月 1 日より前 | 当年 1 月 1 日 |
| 6 月 1 日以上 | 当年 6 月 1 日 |

## 5. 処理手順

| No | 処理 |
|---:|---|
| 1 | Bot 起動後、P2PQuake 監視開始時に住所同期 task を起動する。 |
| 2 | 有効化設定を確認する。 |
| 3 | 同期履歴から最終同期日時を取得する。 |
| 4 | 最新予定同期日を算出する。 |
| 5 | 同期が必要な場合、住所データを取得する。 |
| 6 | 都道府県、市区町村、町域、緯度、経度を `b_geolonia_address` へ upsert する。 |
| 7 | `b_geolonia_sync_state` の最終同期日時を更新する。 |
| 8 | 住所解決用キャッシュをクリアする。 |
| 9 | チェック間隔の経過後、再度同期要否を判定する。 |

## 6. 入出力

| 種別 | 内容 |
|---|---|
| 入力 | 住所データ API |
| 出力 | `b_geolonia_address`、`b_geolonia_sync_state` |

## 7. 異常時の扱い

| 事象 | 扱い |
|---|---|
| 住所データ取得失敗 | エラーをログ出力し、次回チェックで再試行する。 |
| 一部市区町村の取得失敗 | 取得できた範囲を保存し、失敗分は次回以降の同期対象とする。 |
| DB 登録失敗 | エラーをログ出力し、Bot 全体の停止は避ける。 |
