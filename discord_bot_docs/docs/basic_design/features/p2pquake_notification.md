# P2PQuake 通知設計

## 1. 概要

P2PQuake から地震、津波、緊急地震速報関連イベントを受信し、通知設定に従って Discord へ投稿する。
通知本文、震度画像、津波画像を組み合わせ、長い通知は Discord の投稿上限を超えないよう分割する。

## 2. 構成

| 構成要素 | 役割 |
|---|---|
| 監視タスク | P2PQuake WebSocket に接続し、対象イベントを継続受信する。 |
| 通知本文生成 | イベント種別ごとに Discord 投稿用の本文を組み立てる。 |
| 通知送信 | ギルドごとの通知設定を取得し、対象チャンネルへ投稿する。 |
| メッセージ分割 | 投稿上限を超えない単位へ本文を分割する。 |
| 画像生成 | 震源、観測点、津波対象区域を地図画像として生成する。 |
| 座標解決 | 観測点、住所データ、都道府県代表座標から地図描画用の座標を解決する。 |
| 重複抑止 | 直近イベント ID を保持し、同一イベントの重複通知を防止する。 |

## 3. 対象イベント

| 種別 | 内容 |
|---|---|
| 地震情報 | 震源、最大震度、観測点震度を通知する。 |
| 津波情報 | 津波予報・警報の対象区域、到達予想、満潮時刻などを通知する。 |
| 緊急地震速報 | 予測震度、対象地域、震源情報を通知する。 |

## 4. 通知方針

| 項目 | 方針 |
|---|---|
| 送信先 | 通知カテゴリに紐づく有効なチャンネルへ送信する。 |
| メンション | 通知設定にメンションがある場合、先頭メッセージに付与する。 |
| 本文分割 | 安全上限を超える本文は行単位で分割し、長い行は文字数単位で分割する。 |
| 対象区域 | 津波や緊急地震速報の区域は件数で切り捨てず、本文分割により投稿する。 |
| 震度表示 | 観測点または予測区域は震度の高い順に表示する。 |

## 5. 画像生成方針

| 項目 | 方針 |
|---|---|
| 地震画像 | 震源座標または観測点・予測区域がある場合に生成する。 |
| 震源なし | 震源座標がない場合は「各地の震度」として観測点中心の画像を生成する。 |
| 津波画像 | 津波対象区域がある場合に生成する。 |
| 背景地図 | 地理院タイルを利用し、取得済みタイルはキャッシュする。 |
| 座標解決 | 気象庁観測点、住所データ、都道府県代表座標の順で補完する。 |
| 震度点整理 | 震度 3 未満は画像表示対象外とし、表示候補が多い場合は震度 4 以上に絞る。 |
| 震度ラベル | 高震度色では白文字、それ以外では濃色文字を使い、円内の震度値を読めるようにする。 |

## 6. Geolonia 住所データ利用

観測点名に都道府県名が含まれる場合は、都道府県と市区町村を基準に住所データを検索する。
都道府県名が含まれない場合は、市区町村名から都道府県を逆引きし、一意に解決できる場合のみ座標補完に利用する。
