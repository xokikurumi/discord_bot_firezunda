# データ要件

## 1. データ分類

| ID | 分類 | 主な対象 |
|---|---|---|
| DATA-001 | メッセージログ | 投稿、編集、削除、添付、埋め込み、固定状態 |
| DATA-002 | ボイス状態ログ | 参加、退出、移動、ミュート、配信、カメラ状態 |
| DATA-003 | 通知設定 | 通知カテゴリ、送信先チャンネル、メンション、有効状態 |
| DATA-004 | 外部基礎データ | 住所、震度観測点、同期履歴 |
| DATA-005 | 外部イベント | ICS 予定、Niconico 投稿、Niconico 記事 |
| DATA-006 | 分析結果 | メッセージ分析、管理者フィードバック、コミュニケーション傾向 |
| DATA-007 | 自動応答設定 | リアクションキーワード、絵文字、NG 条件 |

## 2. 保存要件

| ID | 要件 |
|---|---|
| DATA-SAVE-001 | Discord の投稿、編集、削除は、後から確認できる粒度で保存できること。 |
| DATA-SAVE-002 | 外部イベントの通知済み状態を保存し、同じ内容の重複通知を抑止できること。 |
| DATA-SAVE-003 | 外部基礎データの同期完了日時を保存し、次回同期要否を判定できること。 |
| DATA-SAVE-004 | 設定系データは有効・無効を切り替えられること。 |
| DATA-SAVE-005 | 分析結果は対象期間、対象単位、算出日時を含めて保存できること。 |
| DATA-SAVE-006 | 管理者が確認した分析フィードバックと補正結果を保存し、以降の分析で参照できること。 |

## 3. 整合性要件

| ID | 要件 |
|---|---|
| DATA-CONS-001 | メッセージ、通知、外部イベントは一意に識別できるキーを保持すること。 |
| DATA-CONS-002 | 同期処理は途中失敗時に、完了していない状態を完了済みとして扱わないこと。 |
| DATA-CONS-003 | テーブル定義は機能単位で文書化し、要件から参照できること。 |
