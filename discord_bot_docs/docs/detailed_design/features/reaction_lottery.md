# リアクション抽選詳細

## 1. 目的

Discord 上でリアクション応募型の抽選を作成し、指定時刻または手動操作で応募者から当選者を選定する。

## 2. クラス構成

| クラス | 役割 |
|---|---|
| ReactionLotteryCog | 抽選コマンド、抽選待機タスク、抽選結果送信を提供する |
| ReactionLotteryService | 終了時刻解析、期限検証、当選者選定、Discord timestamp 生成を行う |

## 3. コマンド

| コマンド | 入力 | 処理 |
|---|---|---|
| `lottery` | なし | 使用方法を送信する |
| `lottery start [winners] [end] [title]` | 当選人数、終了指定、絵文字、タイトル | 抽選募集 embed を送信し、応募リアクションを付与して終了待機タスクを開始する |
| `lottery end <message_id>` | 抽選メッセージID | 実行中の抽選タスクをキャンセルし、即時に抽選を終了する |

`winners` の既定値は 1、`end` の既定値は `1h`、`title` の既定値は `抽選` とする。
応募リアクションの既定値は `🎉` とする。
`winners` が 0 以下の場合はエラーとして利用者へ通知する。

prefix では利用者が `winners` と `end` を入れ替えて指定しても解釈する。
title の先頭 token がカスタム絵文字または英数字を含まない絵文字に見える場合、
その token を応募リアクションとして扱い、残りを title とする。

## 4. 終了時刻解析

終了指定は次の順序で解析する。

| 順序 | 形式 | 内容 |
|---:|---|---|
| 1 | 相対時間 | `30m`、`2h`、`1d` などを現在時刻からの期間として扱う |
| 2 | 絶対日時 | `YYYY-MM-DD HH:MM`、`YYYY-MM-DDTHH:MM`、`MM-DD HH:MM` を日本時間として扱う |

`MM-DD HH:MM` は現在年を補完する。
解析後は UTC aware datetime に変換する。
終了時刻が現在時刻以前、または現在時刻から 7 日を超える場合はエラーにする。

## 5. 抽選開始

1. 終了指定を解析し、当選人数を検証する。
2. 抽選タイトル、当選人数、Discord timestamp 形式の終了時刻を含む embed を送信する。
3. 抽選メッセージに応募リアクションを付与する。
4. 抽選メッセージIDをキーに、終了待機タスク、チャンネルID、当選人数、タイトル、応募リアクション、作成者IDをメモリ上に保持する。
5. 終了時刻まで待機する非同期タスクを開始する。

Cog が unload される場合は、保持している抽選待機タスクをすべてキャンセルしてメモリ上の管理情報を破棄する。

## 6. 早期終了

`lottery end` は、指定 message id の抽選がメモリ上に存在する場合のみ処理する。
実行者が抽選作成者、またはメッセージ管理権限を持つ場合に限り早期終了を許可する。
権限がない場合は抽選管理情報を戻し、抽選を継続する。

## 7. 当選者選定

抽選終了時は対象チャンネルと抽選メッセージを取得し、抽選開始時に保持した応募リアクションを探す。
応募リアクションが存在しない場合は、応募リアクションが見つからなかった旨を送信して終了する。

応募リアクションの利用者一覧から Bot ユーザーを除外し、同一ユーザーを重複除外する。
候補者がいない場合は、応募者がいなかった旨を送信して終了する。
候補者がいる場合は、指定当選人数と候補者数の小さい方を上限としてランダムに当選者を選び、mention 付きで結果を送信する。

## 8. 例外処理

抽選開始時の入力不正は Discord 応答に変換する。
終了待機タスク内で抽選終了処理に失敗した場合は、message id 付きでログ出力し、管理情報を破棄する。
