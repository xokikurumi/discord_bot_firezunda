# 非機能要件

## 1. セキュリティ

| ID | 要件 |
|---|---|
| NFR-SEC-001 | Bot token、DB パスワード、外部 API の接続情報をリポジトリへ直接保存しないこと。 |
| NFR-SEC-002 | 管理系コマンドは Discord の管理者権限を持つ利用者に限定できること。 |
| NFR-SEC-003 | 通知本文やログに機密情報を意図せず出力しないこと。 |

## 2. 可用性

| ID | 要件 |
|---|---|
| NFR-AVL-001 | 外部 API の一時的な失敗で Bot 全体が停止しないこと。 |
| NFR-AVL-002 | WebSocket 監視や定期処理は、例外発生時にログを残し、次回処理を継続できること。 |
| NFR-AVL-003 | 起動時の初期化に失敗した場合は原因を確認できるログを出力すること。 |

## 3. 性能

| ID | 要件 |
|---|---|
| NFR-PERF-001 | メッセージ受信時のログ保存と自動リアクションは、通常利用を妨げない時間で処理できること。 |
| NFR-PERF-002 | 大量データを扱うバックフィル、同期、分析処理は、件数制限またはバッチ単位で実行できること。 |
| NFR-PERF-003 | 重複通知や重複登録を抑止し、不要な DB 更新を避けられること。 |

## 4. 保守性

| ID | 要件 |
|---|---|
| NFR-MNT-001 | 機能ごとに設計書、詳細設計書、テーブル定義、バッチ定義へ追跡できること。 |
| NFR-MNT-002 | CI で Markdown とドキュメントサイトの整合性を検証できること。 |
| NFR-MNT-003 | 追加機能は既存の ID 体系に従って要件を追加できること。 |

## 5. 運用性

| ID | 要件 |
|---|---|
| NFR-OPS-001 | リリース前に lint、ビルド、必要なテストを実行できること。 |
| NFR-OPS-002 | 障害時に設定、ログ、DB 状態から原因調査できること。 |
| NFR-OPS-003 | 定期処理の有効・無効や実行間隔を設定で調整できること。 |
